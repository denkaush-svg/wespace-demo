# WESPACE — демо-стенд

Интерактивный демо-стенд WESPACE: рабочее место брокера коммерческой недвижимости (Дубай).
Витрина: **https://denkaush-svg.github.io/wespace-demo/**

Стенд полностью офлайновый — один HTML-файл, без сервера, без сети, без сборщика.
Открывается двойным кликом и работает так же, как на Pages.

## Что где лежит

| Путь | Что это |
|---|---|
| `index.html` | **Собранный артефакт.** Именно его отдаёт GitHub Pages. **Руками не править** — перезапишется сборкой. |
| `src/index.html` | Точка входа для разработки: подключает `css/` и `js/` обычными тегами. |
| `src/css/` | `tokens.css` (палитра и токены) → `app.css` (компоненты) → `theme.css` (тема). Порядок важен. |
| `src/js/` | 11 модулей, порядок загрузки задан в `src/index.html` и продублирован в сборщике. |
| `src/build.js` | Сборщик: склеивает всё в один файл. |
| `src/test/` | `smoke.js` — прогон в jsdom; `shots.js` — скриншоты и замеры в Chromium. |

Модули по назначению: `icons` (SVG-набор), `photos`/`viz` (картинки в base64 — отсюда почти весь вес),
`fixtures` (демо-данные), `scenarios` (сценарии показа), `finance` (расчёты),
`store` (состояние + localStorage), `engine` (Консьерж и треды), `events` (события сценариев),
`ui` (рендер всех экранов), `main` (роутер и делегирование кликов).

## Как работать

```bash
npm install          # jsdom + puppeteer, только для тестов
npm test             # прогон в jsdom
npm run build        # пересобрать index.html из src/
npm run check        # тесты + сборка
```

Правки вносятся **только в `src/`**, затем `npm run build`, затем коммит — в одном коммите и
исходники, и пересобранный `index.html`. Иначе витрина разъедется с исходниками.

Для разработки удобнее открывать `src/index.html` напрямую: правка `js/` видна по F5 без сборки.

## Сборщик

```bash
node src/build.js                       # -> ./index.html, штамп = текущее время
node src/build.js out.html --stamp 12:00
```

Что делает: три файла CSS в один `<style>` через разделитель из пустой строки, 11 модулей —
инлайном с сохранением отступа, CRLF → LF, штамп сборки в `<title>` и `window.WS_BUILD`.

Сборка **детерминированная**: одинаковый вход даёт побайтово одинаковый выход. Отсюда главный
приём проверки — пересобрать из нетронутых исходников с тем же штампом и сверить с тем, что
опубликовано:

```bash
git cat-file -p HEAD:index.html > /tmp/published.html
node src/build.js /tmp/rebuilt.html --stamp <штамп из опубликованного>
cmp /tmp/published.html /tmp/rebuilt.html      # обязано совпасть
```

Совпадение доказывает, что артефакт собран ровно из этих исходников, и дальше любое
расхождение объясняется только твоими правками.

## Тесты

`npm test` поднимает приложение в jsdom и проверяет инварианты по всем сущностям демо-данных
(8 контактов, 7 сделок, 4 компании): лента событий не пустая нигде, порядок «новое сверху»,
удаление заметки попадает в нужную запись после слияния и сортировки, форма события пишет в
таймлайн своей сущности, обратная датировка встаёт на своё место, отменённые и недатированные
события ведут себя корректно, все экраны рендерятся.

`npm run shots` гоняет настоящий Chromium на двух ширинах, кладёт скриншоты в `.shots/` и
печатает горизонтальное переполнение. **Штатное переполнение на ширине 1100px = 34px, оно
пре-существующее** — не принимать за регрессию. И помнить: длинная строка `--stamp` сама
расширяет шапку и искажает этот замер.

## Демо-данные

В стенде только выдуманные данные: вымышленное агентство, вымышленные клиенты, телефоны
замаскированы, все проверки (KYC, AML, эскроу) — имитация и помечены как DEMO. Реальных
данных, ключей и интеграций в репозитории нет.

## Порядок правок

1. Править `src/`.
2. `npm test` — зелёный.
3. `npm run build`.
4. Коммит вместе с пересобранным `index.html`.
5. Push в `master` — GitHub Pages обновится сам за ~1 минуту.

## Второй стенд: скин WEWALL

`index-wewall.html` — тот же стенд в визуальном языке посадочной страницы WeWall
(библиотека `@wewall/vibe-ui`, 17 компонентов). Проба направления, а не замена: острые углы,
серый холст с белыми поверхностями вместо теней, поля с утопленной заливкой, две толщины
линий, крупные числа Bebas Neue, направляющие с точками, кнопки с заливкой слева.

Сборка строго аддитивная — `src/build-wewall.js` берёт уже собранный `index.html` байт в байт
и дописывает перед `</head>` единственный файл `src/css/theme-wewall.css`. Ни `app.css`,
ни `theme.css`, ни один модуль `js/` не тронуты, поэтому две версии не могут разойтись
в поведении — только в оформлении.

`kit-wewall.html` — витрина компонентов: примитивы библиотеки, переписанные с React/SCSS
на чистый CSS и наполненные содержимым стенда, с разбором «берём / берём с оговоркой / не берём».

```bash
npm run build          # базовый стенд
npm run build:wewall   # -> index-wewall.html   (после build)
npm run build:kit      # -> kit-wewall.html
npm run shots:skin     # сравнительные рендеры двух версий -> .shots/skin/
npm run shots:kit      # витрина на 1440 / 834 / 390 px -> .shots/kit/
```
