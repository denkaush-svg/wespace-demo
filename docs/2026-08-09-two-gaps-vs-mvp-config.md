# Два расхождения стенда с конфигом MVP v3

Найдено 09.08.2026 попутно, при проверке чужого метода планирования на нашей задаче.
Это **факты, а не задачи** — попадают ли они в такт 0.5, решает принципал.

Проверялось по коду `src/js/`, не по памяти.

## 1. Запрос аванса комиссии — в конфиге есть, в стенде нет

Конфиг MVP v3, блок «Клуб · партнёры · деньги», описывает запрос аванса комиссии агентом
(с потолком и статусами рассмотрения).

В коде стенда: `grep -i "аванс\|предоплат\|payout"` по `src/js/*.js` — ноль совпадений по смыслу.
`advance` в `engine.js` — это шаг сценария, не деньги. В кошельке есть «Пополнить», запроса аванса
нет.

## 2. Онбординг первого входа с импортом контактов — в стенде нет

Импорт в стенде живёт в разделе «Объекты» (создать/импорт). Сценария первого входа с загрузкой
контактов из CSV/XLSX и сопоставлением полей нет: `grep -i "онбординг"` — ноль.

## Чего это НЕ означает

Что их «забыли». Оба могли быть сознательно вынесены за такт 0.5 — я этого не знаю и не проверял
по решениям. Здесь зафиксировано только расхождение между конфигом и текущим кодом стенда.

## Откуда взялось

Побочный результат проверки BMAD-METHOD на пригодность: метод прогнали вслепую по тому же конфигу
и сверили его разбор с построенным. Сам метод проверку провалил на другой задаче — материалы в
`wiki-vault/knowledge/90_sources/research/2026-08-09-bmad-superclaude-fitness-test/`. Эти два
пункта — единственное, что из того прогона пережило сверку с кодом.
