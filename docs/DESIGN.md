# Работа над оформлением стенда

Для дизайнера, который правит внешний вид WESPACE самостоятельно.
Документ отвечает на четыре вопроса: что это, как запустить, что можно трогать,
как отдать правки.

---

## 1. Что это

WESPACE — интерактивный демонстрационный стенд: рабочее место брокера недвижимости
в Дубае. Не макет и не прототип в Figma, а работающее приложение, которое показывают
партнёрам и клиентам.

Посмотреть без всякой установки: **https://denkaush-svg.github.io/wespace-demo/**

Технически это **один файл** `index.html` весом около 2,9 МБ — в нём собраны разметка,
стили, скрипты, шрифты и изображения. Такой файл открывается двойным щелчком с диска,
без сервера и без интернета: это нужно, чтобы стенд можно было отправить в мессенджере
и он открылся на телефоне.

**`index.html` править нельзя.** Это результат сборки, он перезаписывается целиком.
Исходники лежат в папке `src/`.

---

## 2. Как запустить у себя

### Путь А — в браузере, ничего не устанавливая (рекомендуется)

На странице репозитория: кнопка **Code** → вкладка **Codespaces** → **Create codespace on master**.

Откроется полноценный редактор прямо в браузере, всё уже установлено. Дальше в терминале:

```bash
npm install        # один раз, при первом запуске
node src/build.js  # пересобрать index.html после правок
```

Чтобы посмотреть результат — откройте `index.html` в списке файлов и нажмите
кнопку предпросмотра, либо скачайте его и откройте у себя.

### Путь Б — на своей машине

Нужен [Node.js](https://nodejs.org) версии 18 или новее.

```bash
git clone https://github.com/denkaush-svg/wespace-demo.git
cd wespace-demo
npm install
node src/build.js
```

Затем откройте `index.html` двойным щелчком. После каждой правки — снова
`node src/build.js` и обновите вкладку.

### Проверка перед тем, как отдать правки

```bash
npm test
```

Около 1 900 проверок, идут примерно минуту. Должно быть `FAILED: 0`.
Что делать, если покраснело, — в разделе 5.

## 3. Из чего состоит оформление

Стили лежат в `src/css/` тремя слоями. Порядок загрузки важен: каждый следующий
может переопределить предыдущий.

| Файл | Строк | Что в нём |
|---|---|---|
| `tokens.css` | 130 | **92 переменные**: цвета, радиусы, тени, отступы, шрифтовая шкала. Основа всего остального. |
| `app.css` | 2860 | Вёрстка экранов и компонентов: карточки, доска, списки, формы. |
| `theme.css` | 320 | Каркас страницы: боковое меню, шапка, вкладка Консьержа, тёмная и светлая темы. |

Отдельно: `theme-a.css` / `theme-b.css` — варианты оформления для сравнения,
`theme-wewall.css` — версия под бренд WEWALL, `static-nojs.css` — вид страницы,
когда скрипты не работают (см. раздел 6).

**Разметка живёт не в CSS.** HTML собирается скриптом `src/js/ui.js` — это двенадцать
тысяч строк, которые строят страницу из данных. Поменять цвет, отступ, размер, тень,
скругление можно целиком в CSS. Поменять **порядок блоков, состав карточки или текст**
— только в `ui.js`, и это стоит делать вместе с разработчиком.

---

## 4. Что можно менять свободно

**`tokens.css` — весь.** Ни одна из 92 переменных не закреплена проверками. Меняя их,
вы перекрашиваете и перенастраиваете плотность всего стенда разом. Это самый быстрый
способ увидеть на экране новое оформление.

**`app.css` — почти весь**, кроме десяти правил из раздела 5.

**`theme-a.css`, `theme-b.css`** — свободно, это и есть площадка для вариантов.

---

## 5. Что закреплено проверками

Десять правил проверяются **по тексту файла**, а не по картинке на экране. Это значит,
что даже переформатирование — перенос на другую строку, лишний пробел внутри
`@media (max-width:860px)` — уронит проверку, хотя выглядеть будет ровно так же.

Так сделано намеренно: за каждым правилом стоит ошибка, которую уже ловили руками.
Менять их можно — но вместе с проверкой, то есть вместе с разработчиком.

### В `app.css`

| Правило | Что оно держит |
|---|---|
| `.start { max-width: 1180px; margin: 0 auto; padding: 26px 30px 80px; }` и `.view { max-width: 1180px; …` | Пульс той же ширины, что остальные экраны. Разъезжались. |
| `@media (max-width: 899.98px) { … .kanban { display: none … }` | Доска сделок прячется на узком экране. Порог продублирован в `ui.js` — менять надо оба. |
| `@media (max-width: 760px) { … .pd-table thead { display: none … }` | Строка дня на телефоне становится карточкой, а не полосой прокрутки вбок. |
| `.dcard-pair { grid-template-columns: 1fr 1fr; align-items: stretch …` | Две карточки в ряду одной высоты. |
| `.dcard-chat .chat { … max-height … overflow-y: auto }` | У ленты внутри карточки свой предел высоты и своя прокрутка. |
| `.deal .dtask` и `.dtask-t` | Строка задачи на карточке сделки и обрезка её заголовка. |
| `.app.nav-railed { grid-template-columns: 64px …` | Ширина свёрнутого бокового меню. |

### В `theme.css`

| Правило | Что оно держит |
|---|---|
| `@media (min-width:861px){ #main{ padding-right:34px; } }` | Вкладка Консьержа у правого края не ложится на содержимое. |
| `@media (max-width:860px){ .cg-tab{ display:none; } }` | На узком экране этой вкладки нет — Консьерж вызывается из нижней панели. |

### В `tokens.css`

| Правило | Что оно держит |
|---|---|
| Переменная `--font-name` объявлена, и имена людей набраны ею | Имена набираются текстовым шрифтом, а не дисплейным. Дисплейный на именах читается плохо. |

### Ещё две проверки на весь CSS

- **Скобки сходятся** в каждом файле — число `{` равно числу `}`. Если проверка
  ругается на это, вы где-то потеряли закрывающую скобку.
- **Каждый класс, который встречается в разметке, описан в CSS.** Если разработчик
  добавил класс, а стиля к нему нет — проверка покраснеет.

## 6. Два правила, которые важнее красоты

**Стенд обязан читаться без скриптов.** Telegram и Почта на iPhone открывают
приложенный `.html` через встроенный просмотрщик, который не выполняет ни одного
скрипта. Поэтому есть `static-nojs.css` — вид страницы в этом режиме. Если правка
делает содержимое видимым только после работы скрипта, на телефоне партнёр увидит
серый экран.

**Ничего не должно выталкивать страницу вбок.** Широкая таблица, длинное слово,
фиксированная ширина — всё, что не помещается в 390 пикселей, получает собственную
прокрутку внутри своего блока, а не двигает всю страницу.

Проверить обе вещи разом:

```bash
py ~/.claude/scripts/html-mobile/check.py index.html
```

## 7. Как отдать правки

Прямо в `master` не пушим — стенд оттуда раздаётся клиентам.

```bash
git checkout -b design/<ваше-имя>
node src/build.js
npm test
git add src/css/         # index.html не коммитим — его пересоберём при слиянии
git commit -m "design: <что поменяли>"
git push -u origin design/<ваше-имя>
```

Дальше на GitHub — **Compare & pull request**. Мы прогоняем проверки и вливаем.

**`index.html` в коммит не включайте.** Он весит 2,9 МБ и меняется целиком при каждой
сборке: два человека, коммитящие его параллельно, получают конфликт на всём файле.
Собранную версию делаем мы при слиянии.

---

## 8. К кому идти

- Правило из раздела 5 мешает задуманному — к разработчику, поправим правило и проверку вместе.
- Нужно поменять порядок блоков, состав карточки или текст — это `ui.js`, тоже к разработчику.
- `npm test` покраснел, и непонятно почему — пришлите вывод целиком, там написано имя проверки.
