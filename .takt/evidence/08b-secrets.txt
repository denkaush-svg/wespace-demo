Шаг 8 (возврат) — проверка на секреты, выполненная заново по действительной базе

ПОЧЕМУ ПЕРЕЗАПУСК. Первая запись шага 8 недействительна. Её команда бралась от
базового коммита 00fcbee3ad..., которого в этом репозитории нет (он из репозитория
wewall). Диапазон не резолвится, git diff падает, grep получает пустой вход, находит
ноль совпадений — и «0 hits — scan clean, RC=0» записалось как пройденная проверка.
Скан не нашёл секретов потому, что ему нечего было смотреть.

Найдено не мной, а шагом 14 (сводка). Проверено мной лично:

    $ git diff 00fcbee3adc120856679d7f5535efd91a10da691..HEAD --stat
    fatal: Invalid revision range 00fcbee3adc120856679d7f5535efd91a10da691..HEAD

Это третье последствие одной неверной строки в начальной записи журнала. Первые
два — мёртвый гейт границы (найден шагом 10) и невозможность машинно сверить
правки с 00-granica.txt. Третье — вот это: заявленная проверка безопасности, не
проверившая ничего и принятая оснасткой как зелёная.

ПРОГОН ЗАНОВО, по действительной базе 88c4a8e (её называют и 00-intent.md:4, и
00-granica.txt; принадлежность подтверждена: git cat-file -t 88c4a8e => commit,
merge-base --is-ancestor 88c4a8e HEAD => да).

    $ git diff 88c4a8e..HEAD -- . ':(exclude).takt/' > /c/temp/scan-input.txt
    diff bytes: 98258
    diff lines: 1702

Сравнение объёмов и есть доказательство разницы: прошлый прогон сканировал 0 байт,
этот — 98 258 байт реальных изменений.

    $ grep -inE 'AKIA[0-9A-Z]{16}|gh[pousr]_[A-Za-z0-9]{20,}|xox[baprs]-|
                 sk-[A-Za-z0-9]{20,}|BEGIN [A-Z ]*PRIV[A-Z ]*KEY|
                 s[e]cret[_-]?key|p[a]ssw[o]rd\s*[:=]\s*["'][^"']|
                 ap[i]_?k[e]y\s*[:=]\s*["'][^"']|
                 t[o]ken\s*[:=]\s*["'][A-Za-z0-9]{16,}' scan-input.txt

    hits: 0
    grep RC=1  (1 означает «совпадений нет» — нормальный исход чистого скана)

Классы, которые ищет набор: ключи облачных провайдеров (AWS), токены GitHub и Slack,
ключи вида sk-, блоки приватных ключей, и присваивания вида «ключ/пароль/токен = "..."»
с непустым значением достаточной длины.

ИСХОД: чисто. В 1702 строках изменений этого прогона нет ни одного совпадения ни по
одному классу.

историю репозитория и не рабочее дерево целиком. Секрет, попавший в репозиторий до
88c4a8e, ею не будет найден — для этого нужен отдельный проход по истории, и он в
