## Триаж ведущего

Находки внешнего ревью — непроверенный вход, а не приговор: на прогоне Task 8 вердикт
«ДЕФЕКТ» при проверке оказался недостижимым в бою. Поэтому каждую сверил по коду сам.

**Все четыре подтверждаю. Ни одна не отклонена.**

**Находка 1 — порядок массива решает, `requestId` не имеет приоритета.** Подтверждаю:

```
$ sed -n '6248p' src/js/ui.js
    const r = (D().requests || []).find((x) => cs[x.id] && (x.id === e.requestId || x.clientId === e.clientId));
```

`[проверено прогоном: `sed -n '6248p' src/js/ui.js`]` — `find` возвращает первое совпадение
в порядке массива, а условие принимает и собственную заявку сделки, и любую заявку того же
клиента наравне. Собственная заявка обязана побеждать, и не побеждает.

**Находка 2 — закрытая заявка становится источником действующего расхождения.**
Подтверждаю: в резолвере нет ни одной проверки состояния заявки-источника. Хуже того,
подпись, которую я на прошлом шаге похвалил, утверждает «расхождение до сих пор не снято» —
то есть карточка сделки делает утверждение об актуальности, которого никто не проверял.
Это ровно тот дефект, который правка чинила: интерфейс выдаёт историю за текущий факт.
Правка перенесла его с одного места на другое.

**Находка 3 — валидатор падает вместо списка находок.** Подтверждаю:

```
$ sed -n '26p;41p' src/test/validate-data-graph.js
    (arr || []).forEach((x) => { if (x && x.id) s[x.id] = true; });
    if (таблица[значение]) return;
```

`[проверено прогоном: `sed -n '26p;41p' src/test/validate-data-graph.js`]` — `(arr || [])`
подставляет пустой массив только при `null`/`undefined`; объект вместо массива проходит
дальше и роняет `forEach`. Элемент `null` внутри коллекции роняет обращение к полю.

**Находка 4 — и это самая тяжёлая.** Отсутствующая коллекция даёт `[]`, то есть
**«разрывов нет» вместо «проверить не удалось»**. Проверка, которая молча вернула пустой
список на входе, который не смогла разобрать, выглядит пройденной и ею не является — это
именно то, против чего заведён третий исход во всём такте, и валидатор его не имеет.
Отдельно: `таблица[значение]` при числовой ссылке `123` попадает в ключ-строку `'123'`,
то есть числовая ссылка молча считается годной.

## Два наблюдения об оснастке, не о задаче

**Стоимость внешнего узла впервые измерена: 44 557 токенов.** На прогоне Task 8 и на базе
она записывалась как «не измерено», потому что подключение шло по протоколу, который
расхода не сообщает. Командная строка его печатает. Дыра, объявленная в условии готовности
№4, закрывается сменой способа вызова, а не отсутствием возможности.

**Узел работал две минуты и стоил 44 тысячи токенов** — вчетверо дешевле любого
собственного узла на этом прогоне (реализация 193 тысячи, приёмочные тесты 209 тысяч) — и
нашёл четыре дефекта в правке, у которой 2131 проверка зелёная. При этом до начала работы
он стоил **четыре отказа подряд**: подключение по протоколу держит старый двоичный файл,
вторая модель недоступна для этой учётной записи, командная строка не приняла флаг из другой
версии, и исчерпан лимит с ожиданием до сброса. Ни один из отказов не про качество ревью;
все четыре — про то, что узел живёт в чужой оснастке, которая меняется независимо от нашей.
