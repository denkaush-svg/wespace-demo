# Шаг 11 — закрытие после устранения расхождений

Первая запись шага 11 (`11-joints.md`) сделана с пометкой «найдена поломка»: сверка стыков нашла два расхождения контрактов, ни одно из которых не было пересказом находок шага 7. Оба устранены.

## Судьба обоих расхождений

Состояние снято прогоном:

```
node src/test/smoke.js         → checks: 1989  passed: 1989  FAILED: 0
node server/test/proxy-test.js → all proxy checks passed
node src/test/live-ux.js       → checks: 16  passed: 16  FAILED: 0
git status --porcelain         → (пусто)
```
`[проверено прогоном: `node src/test/smoke.js`]` · `[проверено прогоном: `node server/test/proxy-test.js`]` · `[проверено прогоном: `node src/test/live-ux.js`]`

**1. `done.model` терялся в транспорте — закрыто.** Сервер слал `model` в событии `done` (`proxy.js`), клиент собирал метаданные ответа без него (`live.js`). Теперь поле доходит до ответа. Откат правки красит `live · which model answered travels with the reply too, not dropped in transport` `[model=null]` — проверено мутацией дважды, кругом правки и независимо слепой перепроверкой.

**2. Сторож не был связан с серверным лимитом — закрыто, и глубже, чем просила находка.** Сервер публикует действующий `stallMs` на стадии `accepted`, клиент его перенимает. Откат клиентской строки красит `turn-state · a turn adopts the silence limit the server announced instead of its own default ceiling` `[inFlight=false aborted=true]`; откат серверной — две проверки в proxy-наборе.

Второе расхождение оказалось симптомом более глубокого дефекта, и это стоит записать отдельно. Круг правки, закрывая его, вынужденно ограничил принятие серверного лимита через `Math.max` и честно объяснил почему: «серверный лимит про молчание, а этот считает весь звонок». Из этой оговорки вскрылось, что клиентский сторож вообще мерил не то — дедлайн на весь звонок вместо молчания, — и обрывал ответы, которые печатались дольше потолка, показывая «соединение оборвалось» на приходящем потоке. То есть шаг 11 нашёл не только названное расхождение, но и, через него, дефект, внесённый шагом 9 этого же прогона. После исправления семантики оговорка снялась: обе стороны меряют молчание, клиент берёт серверный лимит плюс запас и остаётся ровно «чуть больше», как требует §2 намерения.

## Три стыка, которые сошлись

Имена стадий (`proxy.js` → `live.js` → `engine.js`), форма объекта хода у всех шести потребителей, и контракт отмены. Последний важен отдельно: шаг 7 прямо записал, что не проверял цепочку «настоящая кнопка браузера → fetch → прокси → освобождение слота» единым прогоном. Шаг 11 прогнал её как один сигнал против живого прокси при `concurrency=1` и закрыл собственный объявленный пробел предыдущего шага.

## Замечание о самой роли

Роль стояла на испытании: за четыре предыдущих прогона она не нашла ни одного дефекта первой, трижды пересказывала чужие находки, один раз не оставила артефакта, один раз выдала ложное утверждение. В задании это было названо прямо, вместе с условием, что пересказ находок шага 7 не засчитывается. Роль написала и прогнала собственную пробу против настоящего прокси с поддельным CLI, дала два непересказанных расхождения с дословным выводом и закрыла пробел предыдущего шага. Это довод в пользу того, что дело было в задании, а не в модели, — и данные для решения о снятии испытания.
