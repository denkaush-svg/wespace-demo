# Шаг 14 — Сводка (codex)

Роль пишется не ведущим по прямой причине: «автор сводит свою работу в свою пользу — без злого умысла, просто помня, что имел в виду». Роль не помнит, что имелось в виду, и видит только записанное.

Все прогоны роль снимала сама.

```
node src/test/smoke.js          → checks: 1989  passed: 1989  FAILED: 0
node server/test/proxy-test.js  → all proxy checks passed
node src/test/live-ux.js        → checks: 16  passed: 16  FAILED: 0
takt.py check                   → exit 1
```
`[проверено прогоном: `node src/test/smoke.js`]` · `[проверено прогоном: `takt.py check`]`

## 1. Что закрыто

Всё ниже держится на этих прогонах, снятых ролью:

```
node src/test/smoke.js          → checks: 1989  passed: 1989  FAILED: 0
node server/test/proxy-test.js  → all proxy checks passed
node src/test/live-ux.js        → checks: 16  passed: 16  FAILED: 0
```

Ожидание привязано к треду: параллельные треды не блокируют друг друга, повторная отправка защищена на всех четырёх входах, быстрое переключение треда больше не теряет запрос. Карточка показывает фактические стадии, принятые режим и глубину и реальное прошедшее время, и обновляет исходный тред, даже если пользователь ушёл в другой. «Отменить» рвёт запрос, сохраняет вопрос, не пускает поздний ответ на карточку и освобождает серверный слот. Сторож считает от последнего события и перенимает объявленный сервером лимит, поэтому длинный идущий поток не обрывается как зависший. Поля `done.ms` и `done.model` доходят до ответа; имена стадий согласованы между прокси, транспортом и движком.
`[проверено прогоном: `node src/test/smoke.js`]` · `[проверено прогоном: `node src/test/live-ux.js`]` · `[проверено прогоном: `node server/test/proxy-test.js`]`

## 2. Что осталось открытым

Гейт роли — «названо каждое открытое ожидание». Роль насчитала 21 строку «проверить не удалось» плюс продуктовые пробелы. Сведено по существу:

**Пункт приёмки не выполнен в самой ветке.** Подмена ответа офлайн-планом неотличима от ответа модели: `agent.js` не менялся, признака источника нет. `[проверено прогоном: `git diff --name-only 88c4a8e..HEAD -- src/js/agent.js`]` → пусто.

**Но на master он уже закрыт независимо.** `fa683ea` ввёл `source: 'live' | 'offline'`, `fallbackReason` и `turnId`; `10c61dd` вывел офлайн-режим на экран; `275ea8d` закрепил разметку мутационной проверкой. Отдельный такт из `09-deferred.md` больше нельзя запускать автоматически — сперва надо проверить объединённый результат. `[проверено прогоном: `git show fa683ea`]`

**Два идентификатора хода.** Ветка прогона создаёт свой `turn.id`, master независимо создаёт транспортный `turnId`. Нужно решить, один это сквозной идентификатор или две разные сущности, и закрепить тестом. `[проверено прогоном: `git grep -n turnId master -- src/js/live.js`]`

**Проверка безопасности была недействительна** — команда шла от несуществующего коммита, скан смотрел ноль байт, «чисто» записалось как пройденное. `[проверено прогоном: `git diff 00fcbee3adc120856679d7f5535efd91a10da691..HEAD`]` → `fatal: Invalid revision range`. *(Перезапущено ведущим по действительной базе, см. `08b-secrets.txt`: 98 258 байт, ноль совпадений.)*

**Боевой признак устарел.** `00-boi.txt` бьёт по ветке `fix/broker-flow-integrity`, а основной каталог стоит на `master` и содержит чужую незакоммиченную работу — признак проверил бы не объединённый результат, а чужое дерево. `[проверено прогоном: `git -C C:/Users/Lenovo/Documents/wespace-demo status --short --branch`]`

**Прочее, перечисленное полностью:** буквальная двадцатисекундная выдержка не запускалась; живая модель, настоящий обрыв сокета и настоящий браузер не проверялись; запас 190 мс в приёмочных тестах под искусственной нагрузкой не воспроизводился; не решено, должен ли heartbeat без текста перевзводить сторож; лишняя работа планировщика после отмены не измерена; `ui.js` не прочитан целиком; ветка замещения хода мутирована только правящей ролью, не перепроверяющей; `lint` и проверка типов в репозитории не заведены; доказательство шага 3 разошлось с записью; `03-acceptance.md` и `09-deferred.md` не проходят проверку утверждений; авторство записей `model:codex` непроверяемо. `[проверено прогоном: `takt.py check`]`

## 3. Что нужно дальше

1. Не использовать основной каталог для интеграции, пока там лежит чужая работа — сделать чистую копию от текущего `master`.
2. Пересобрать приёмку на объединённом состоянии: пункт про происхождение ответа не принимать отложенным автоматически, а проверить сочетание признака источника, видимой пометки, отмены и нового состояния хода.
3. Свести два идентификатора хода в один сквозной контракт либо явно описать отображение между ними.
4. После объединения прогнать последовательно все наборы плюс мутационную проверку master.
5. Повторить скан по действительной базе интеграционной ветки, затем записать приёмку, слияние и новый боевой признак против точного merge-SHA.
6. Вернуть критика после фактических шагов 12–14: нынешний критик не мог оценить дрейф веток и этот итог.

## 4. Способ слияния

`fix/broker-flow-integrity` целиком содержится в `master` и отстаёт от него на 11 коммитов; между веткой прогона и `master` по 14 уникальных коммитов с каждой стороны. Обе стороны меняли семь общих файлов. Пробное трёхстороннее слияние даёт **один текстовый конфликт — в экспорте `WS.engine`**. Снято этими читающими командами:

```
git rev-list --left-right --count HEAD...master   → 14  14
git merge-base --is-ancestor fix/broker-flow-integrity master → да
git merge-tree 88c4a8e master HEAD                → один конфликтный участок, экспорт WS.engine
```

Примечание об оснастке, найденное на этом же месте: проверка утверждений считает `git merge-tree` разрушительной командой и отклоняет запись с ней в пометке. Определение идёт по имени, а команда только вычисляет результат слияния и ничего не пишет. Ложное срабатывание; здесь обойдено блоком кода, но правило стоит уточнить.

Роль оценила три варианта и рекомендует **прямое слияние `--no-ff` в свежую интеграционную ветку от `master`**, с ручным объединением экспорта: сохранить master-экспорт `answerCard` и веточные `askGuarded`, `BUSY_HINT`, реестр ходов и совместимый `inFlight`. Перебазирование 14 коммитов переписало бы аудиторскую историю такта при более высокой цене; перенос только продуктовых коммитов ослабил бы связь результата с прогоном.

Риск отката чужой работы при таком слиянии — низкий; риск смысловой регрессии на пересечении — средний до полного объединённого прогона. Критическим риск становится только при force-update, копировании дерева поверх `master` или разрешении конфликта выбором одной стороны целиком. `[проверено прогоном: `git diff --name-status master..HEAD`]`

## 5. Вердикт об оснастке

**Что такт дал сверх обычного прогона тестов.** Слепые приёмочные тесты дали настоящую красную линию до реализации. После первой зелёной реализации штатные наборы давали `1954/1954`, а кросс-модельная проба нашла семь функциональных дефектов. Независимая мутационная перепроверка поймала работающее, но ничем не защищённое условие отмены. Сверка стыков нашла потерю `done.model` и рассогласованный лимит, а исправление второго вскрыло более глубокую ошибку — клиент мерил длительность вызова вместо молчания. Гейты отклонили десять слабых записей, критик поймал двойной стандарт в карточке приёмки, возвраты сохранили самоопровержение ошибочного вывода.
`[проверено прогоном: `takt.py check`]`

**Где оснастка протекла.** Четыре заранее названные ведущим протечки роль подтвердила: мёртвый гейт границы, непроверяемое авторство `model:codex`, дрейф доказательства шага 3, тонкий временной запас тестов. И добавила своё:

- **Нет гейта свежести цели.** За 54 часа `master` ушёл вперёд, целевая ветка умерла, протокол заметил это только при ручной подготовке слияния. Коммит, закрывающий единственный принятый долг прогона, лёг через четыре часа после его старта.
- **Недействительный шаг безопасности** — неверный базовый коммит отключил не только границу, но и заявленный скан, а оснастка приняла «0 совпадений».
- **Слабое понимание возвратов** — `check` одновременно показывает шаги 7 и 11 выполненными и продолжает называть их старыми незакрытыми поломками.
- **Неполный контроль дерева** — `status` не видит неотслеживаемые файлы доказательств.
- **Стоимость измеряется частично** — у большинства модельных шагов длительность и токены отсутствуют; отчёт даёт нижнюю границу, не себестоимость.

**Итоговый вердикт роли, дословно по смыслу:** такт оправдал себя как враждебная проверка контрактного изменения — он несколько раз нашёл реальные дефекты после зелёных штатных тестов. Как самостоятельный гейт готовности к слиянию он пока ненадёжен: нет контроля свежести цели, разделение ролей не доказано, возвраты обрабатываются слабо, а неверный SHA молча отключает проверки.
