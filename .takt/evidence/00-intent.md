## 1. Зачем

Сейчас у Concierge один глобальный индикатор ожидания и декоративный таймер, который
не отражает реальное состояние запроса к серверу (`server/proxy.js`). Из этого
вытекают три поведенческих дефекта, которые план фиксирует напрямую:

- повторная отправка в занятом треде запускает второй запрос вместо блокировки;
- нет способа отменить зависший запрос — только ждать или перезагружать страницу;
- прогресс-текст показывает придуманные стадии («Формулирую ответ»), а не то, что
  реально произошло на сервере (`accepted`/`model_started`/первый `delta`).

Это ровно тот класс дефекта, который трогает контракт между клиентом и сервером
(протокол SSE-событий, форма card-состояния), а не локальную деталь одного модуля —
отсюда класс `contract`, а не `local`.

## 2. Что входит (граница — отдельным файлом `00-granica.txt`)

- Состояние одного turn на треде (не глобальное поле): `id`, `threadId`, `status`,
  `stage`, `startedAt`, `lastProgressAt`, `mode`, `depth`, `abortController`,
  `messageId` — как задано в плане.
- Блокировка повторной отправки в занятом треде (UI + Enter).
- `AbortController` в `WS.live.ask()` и кнопка «Отменить»; отмена закрывает fetch,
  `res.on('close')` на прокси останавливает CLI-процесс.
- Реальные стадии вместо декоративных: `context_ready → accepted → model_started →
  web → streaming → complete/failed/cancelled`, эмитируемые `server/proxy.js` только
  по факту события.
- Таймер по `Date.now() - startedAt`, обновляющий карточку исходного треда даже при
  переключении пользователя на другой тред.
- Явные исходы отказа: оффлайн-план с пометкой «нейросеть не ответила», либо `failed`
  с «Повторить».
- Watchdog клиента чуть больше серверного stall limit — ни один turn не должен
  оставаться `running` после разрыва потока.
- Тесты: расширение `src/test/smoke.js` и `server/test/proxy-test.js`, новый
  `src/test/live-ux.js`, новый npm-скрипт `live:ux` (не включён в обычный `npm test`).

## 4. Чем меряем (приёмка, дословно из плана)

- Через 20 секунд таймер показывает реальное значение, не `0 с`.
- Одновременно виден принятый server `mode`/`depth`.
- Второй вопрос в занятом треде не создаёт перемешанную карточку и не даёт второй
  сетевой запрос (числовой критерий: количество исходящих запросов не растёт).
- «Отменить» заканчивает запрос и освобождает server concurrency slot
  (`call.cancel()` в proxy-тесте).
- Ошибка, fallback и успех визуально и по данным различимы.
- Тест с отложенным async-ответом: через 2,5 с DOM показывает время не меньше «2 с»;
  после resolve карточка ожидания исчезает.
- Тест переключения тредов: таймер/итог обновляются в исходном треде, а не в
  активном.
